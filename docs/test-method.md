# 验证方法：地址扫描

## 不用典型用例的原因

错误集中在几个窄带上，常规前缀与常规地址不落在这些位置：

- 前缀长度取整的临界点：0/1、31/32、127/128
- 相邻前缀重叠时，删除顺序不同导致的状态残留
- 本地刚溢出到远端的那一条
- 压缩进行到一半的中间态

典型用例覆盖不到上述位置，改为按维度铺开扫描。

## 扫描维度

| 维度 | 取值 |
|---|---|
| 前缀长度（v4） | 0, 1, 8, 16, 24, 30, 31, 32 |
| 前缀长度（v6） | 0, 1, 32, 48, 64, 96, 122, 127, 128 |
| 地址形态 | 全 0、全 1、交替 `AA/55`、同族相邻、随机 |
| 模式 | 本地（不溢出）、远端（溢出） |
| 规模 | 单条、批量、接近满表、超表（应报错，不能静默丢弃） |
| 操作序 | 纯插入、纯删除、插删交替、覆盖更新 |

全组合数量太大，实际做两两组合加重点三维：长度乘形态全扫，模式乘操作序只扫长度边界那几档。

## 三层比对

只比查表结果无法区分编码错与查找错，分三层比对：

| 层级 | 比对内容 | 定位的问题 |
|---|---|---|
| L1 编码 | 下发后回读整表，与期望的 `(key, mask, payload)` 逐字段比 | 位打包错、大小端错、mask 生成错 |
| L2 查找 | 逐条 `lookup`，比命中前缀长度与下一跳 | 拼接不完整、优先级仲裁错、部分命中 |
| L3 账目 | 占用行数与分配器位图、碎片率自洽 | 泄漏、重复释放、空洞未回收 |

L1 通过后再看 L2。先看 L2，容易跟着错的期望值改。

## 期望值的来源

参考实现独立于被测实现编写，期望值不由被测侧推导。朴素最长匹配，遍历全部前缀取最长：

```python
def reference_lookup(prefixes, addr):
    best = None
    for p in prefixes:
        if (addr & p.mask) == p.masked_key:
            if best is None or p.key_len > best.key_len:
                best = p
    return best
```

O(n)，慢，但跟被测实现不共用一行代码。被测侧走的是行分配、锚行绑定、SRAM 偏移这一整套流程，两边对不上就是模型错了。

扫描规模受此限制，控制在几百条前缀、几千个采样地址。

## 失败输出

失败输出带全上下文：

```
FAIL len=127 pattern=OUTSIDE addr=0x20010DB80000000000000000000001FF
     expect: key_len=127 next=v6-127-0
     actual: key_len=122 next=v6-127-0
     hint:   length mismatch: anchor span or mask likely wrong
```

前缀长度、探测类型、地址、期望与实际、锚行行号与 span 都在里面，可以直接判断是取整算错
还是续行没绑上。

## 两类已知误报

扫描前先排除以下两种，否则会被当作缺陷追查：

1. 压缩中间态。触发阈值压缩后立刻读表，可能读到搬运到一半的状态。验证时在压缩前后加
   同步点，或者停掉自动压缩再测分配逻辑。
2. 写后立即读。真实硬件有写延迟，行为模型立即生效，两者混在一起会出现假阳性。模型和
   真机分开跑，不要放进同一轮断言。

## 运行

```
python tests/test_sweep.py
```

无第三方依赖。输出每个前缀长度的通过/失败统计，失败时打印上面的上下文块。

只跑某一档：

```
python tests/test_sweep.py --len 127
python tests/test_sweep.py --pattern OUTSIDE
```

可选值：`BASE`、`PLUS1`、`MINUS1`、`OUTSIDE`。
